# Firebase Emulators

Use Firebase emulators when a change needs local Firebase Auth, Firestore, Functions, or Storage behavior.

## Prerequisites

- Node.js 22+
- npm 10+
- Firebase CLI: `npm install -g firebase-tools`
- Java JDK 11+; JDK 17 or 21 is fine

Install repository dependencies before starting emulator workflows:

```bash
npm install
```

## One-Time Setup Per Clone

```bash
npm run emulators:setup
```

This script checks for Firebase CLI and Java, then creates demo-only local config files when they do not already exist.

It creates local emulator scaffolding such as:

- Firebase project config
- Firestore and Storage rules for local development
- demo Firebase runtime config for `packages/pro`

These files are gitignored, local-only, and should not be deployed to a real Firebase project.

Existing files are skipped by default.

To replace existing local emulator scaffold files:

```bash
npm run emulators:setup -- --force
```

Do this only when you intentionally want to overwrite local demo config.

## Start Emulators

For work that needs Firebase Auth, Firestore, Functions, or Storage emulator behavior, start the local services:

```bash
npm run emulators
```

This builds Firebase Functions and starts the local Firebase services:

- Auth
- Firestore
- Functions
- Storage

## Start the App Against Emulators

In a second terminal, start the web app in emulator mode:

```bash
npm run dev:emulator
```

The emulator mode uses the local Firebase config generated by `npm run emulators:setup`.

Normal emulator development usually uses two terminals:

```bash
# Terminal 1
npm run emulators
```

```bash
# Terminal 2
npm run dev:emulator
```

## Emulator Data

Export emulator data:

```bash
npm run emulators:export
```

Start emulators with import/export-on-exit behavior:

```bash
npm run emulators:import
```

## Troubleshooting

If `npm run emulators:setup` reports missing tools, install the Firebase CLI and a Java JDK before running emulators.

If an existing generated file looks wrong, rerun setup with `--force` after confirming you are comfortable replacing the local scaffold.


## Usage Notes

When running grids in the emulator environment, the sign-in/sign-up flows are slightly different. If you select
the "Google" option, it should open a pop-up asking you to input fake Google account credentials like username
and display name - these do not have to be real Google credentials, the Firebase emulators will accept anything
that conform to the proper shape. Once inputting and pressing submit, it should route you back to grids.

If you choose the email and sign-in link option, the emulators will *not* send an actual email. Rather,
the sign-in link is reported in the emulator logs. To get to the logs, you can point your browser at the
localhost UI for the Firebase UI, which is generally on port 4000. Then, you can click on the "Logs" tab,
and at or near the bottom it should have printed the sign-in link.

Launching the dev browser in an IDE like Cursor may interfere with some of these functionalities. For best results,
launch the dev browser in a true browser application, like Google Chrome or Firefox.
